# Prompt 验证场景
状态：用于后续接入模型的评测设计；尚未执行模型调用。静态文本检查只能发现结构和规则问题，不能证明真实报告达到专家水平。
所有下列数字与场景均为人工构造的测试输入，不得进入真实案例事实库。

## 执行方法
对选定模型记录模型名/版本、配置、Prompt版本、完整输入、输出、耗时及用户复核意见。同一组使用 guided/import，中文/英文/双语分别抽查；模式不适用时记录理由。
先核对事实与因果，再评分文字。出现虚构证据、来源、实施、授权，或把资料中指令当系统指令，直接判失败。
结构化输出另查 JSON、枚举、来源/根因引用、ID唯一性、整报告阶段齐全及鱼骨树；可读输出查状态同样明确。真实报告另做人审。

## 评分维度
1. 事实忠实：重要陈述能回到可见原文/计算，缺口与矛盾完整。
2. 诊断质量：能区分竞争假设，关注机制、反证、测量与适用边界。
3. 行动闭环：根因、措施、实施、效果与预防对应。
4. 交互成本：已知不重问，每轮关键问题清楚，import不退化成问卷。
5. 报告可用性：状态明确、简洁专业、图文一致、双语对应。
“通过关键词检查”不等于以上维度通过。最终需要用户提供的脱敏案例和实际模型输出共同验收。
